# 13 November 2026 — gallery adopts the Round 7 workout presentation

Intent: make the gallery the accepted visual source the build can adopt. Eric found that the build had drifted from
both the gallery and the approved Round 7 review app. A side-by-side review (A1) found the gallery itself only
close-ish to Round 7. The owner's rule for the fix: keep the gallery's effect layer (CRT field, glass, echoes,
button glow); everything else returns to Round 7. Tracking lives outside this repo, in the support-tooling
`GALLERY-ADOPTION-PLAN-2026-11-13.md` (A2) and `EXECUTION-LOG.md`.

Base: `eded158` (the previously accepted gallery). That commit had never been pushed to GitHub. It existed
only in a local bundle, so the build could never adopt it byte for byte. This branch carries it.

## What changed

- **Round 7 source brought in.** The real Round 7 workout presentation code
  (`codex/workout-review-r7-2026-11-03` at `daa165f`) was applied as a 3-way patch.
  - Conflicts were resolved in `set-effort.tsx`, `set-logging-sheet.tsx`, `workout-chrome.tsx` and `gallery-registry.tsx`.
  - `WorkoutExperiencePresentationProvider` switches the look on.
  - The effect files are unchanged except one owner-requested value: the screen-edge blur, `perimeter.blurPx`, from 1.6 to 1.2.
- **Owner follow-ups after review** (37 of 39 states marked right, 2 unsure):
  - the circuit entry dialog shows the between-rounds rest at its top;
  - the Movement note dialog has a plain title, the movement name as the field label, and a full-width Save note button;
  - Review's round rest is blue with the Rest glyph again.
- **`/gallery/refinements`** now mounts the real components on a memory-only runtime
  (`src/dev/gallery-refinement-runtime.tsx`). "Open …" clicks the same controls a person would.
  - Feedback, rest day, overview and the Generate/Setup/History scene are composed from Round 7 parts, because those screens need an account.
  - The old hand-built `src/ui/refinements/*` copies and their duplicate CSS are removed.
- **Non-visual:**
  - optional `now` clock on `TimedWorkoutFlow`;
  - `PreviewBlockCompletion` and `PreviewSetLogging` in their owner files, so the single-owner tests hold;
  - the logging dialog's height cap moved from `calc(100dvh - …)` (forbidden by the app-shell test) onto the open dialog box, with the same 40px total clearance. Frame positions were measured identical at 390px.
- **Tests:** 14 test files that expected the pre-Round 7 layout or timer were updated to the approved look. No test was skipped or deleted.

## Failures and corrections

- 48 tests failed after the merge. Twelve of those files were byte-identical to Round 7's own copies, so Round 7 had never updated them.
- Two repository rules failed and were fixed in source rather than in tests: the dialog height cap, and a second block-completion provider.
- Visual checks caught three gallery-only differences:
  - set-logging dialogs used the phone 14px small-label tier (in the app they mount outside Screen and use 12px);
  - the circuit round time read 00:00 because the driver pressed Finish before the round clock re-read;
  - timed cards were headed "1 MOVEMENT" because no section label was provided.
- A first proposal for the dialog cap used 16px clearance. Measurement showed the original was 20px per side, and it was corrected.

What changed, all intended to be invisible:

- **Timed results form** submits through `useInvalidFocus` (formFocus rule).
- **Rounds counter** is a tap-only `<output>`, as the build's accepted counter decided (text-entry rule).
  - Same height as the old field (`line-height: normal`).

  - Countdown in a dialog: the wrapper is a column.
  - Timed clock: the min-height rule was redundant and is removed.
  - Header timer padding now targets `.clr-timer-frame__readout`.

`/gallery`, at 390 and 320, before and after (54 timers).
