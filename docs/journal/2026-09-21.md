**Branch:** `agent-runner/task-003-a1-aabb4b39` · **Intended outcome:** production deploys on

### Starting state

### What changed locally

- **`vercel.json`** (new). Build contract plus the SPA rewrite:
  - `installCommand: npm ci` and `buildCommand: npm run build` — the same lockfile-exact install
    and the same command CI runs, so a preview cannot resolve a dependency the PR did not pin.
  - `outputDirectory: dist`, `framework: vite`.
  - one rewrite, `/(.*)` → `/index.html`. Vercel serves a real file from `dist/` before it
    consults a rewrite, so hashed assets are unaffected and only unmatched paths fall through.
  - `github.enabled: true`, which is the setting that produces the per-PR preview and the
    production promote on `main`.
- **`.env.example`** (new). `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`, names and
  placeholders only, with the Preview-scope warning and an explicit note that
  `SUPABASE_SERVICE_ROLE_KEY` and `ANTHROPIC_API_KEY` are not `VITE_` variables and do not
  belong in this file. `.gitignore` already carried `.env.*` plus `!.env.example`, so no change
  was needed there.
- **`src/test/deploy-config.test.ts`** (new, 15 tests). Asserts the build contract, that
  `outputDirectory` equals what `vite.config.ts` actually writes (it reads the config rather
  than restating `dist`), that the rewrite is a single catch-all to `/index.html`, and — by
  compiling the `source` pattern to a RegExp — that it matches `/`, `/history`,
  `/history/2026-09-21`, `/workout/<uuid>`, `/settings/locations` and a deeply nested path. It
  also holds the environment contract: every `VITE_` name app-owned source reads must appear in
  `.env.example`, no value may look real (a JWT-shaped string or a non-placeholder), and no
  `VITE_`-prefixed name may carry a server-side secret.
- **`DEVELOPMENT.md`**: new *Deployment* section — what triggers a deploy, why the rewrite
  exists (without it `/history` is a CDN 404 before any JavaScript runs, so the app's own 404
  screen never gets the chance to render either), and the environment-variable contract.
- **`README.md`**: a short *Deploys* section and a pointer to `.env.example`.
- **`PROJECT_MAP.md`**: rows for `vercel.json` and `.env.example` — a new deployment boundary,
  which is the bar the map sets for an entry.

Nothing changed in GitHub or in Vercel from this workspace. The execution contract for this task

## PWA-01 — Installable PWA (issue #64)

**Branch:** `agent-runner/task-064-a1-5a01b586` · **Intended outcome:** a manifest, a chamfered
icon set, theme colour and iOS meta, and an app-shell-only service worker — installability
passing and the shell loading offline, with no data ever cached.

### What changed locally

- **`public/`** (new directory, now in `PROJECT_MAP.md`): files a browser fetches by fixed URL.
  - `manifest.webmanifest` — `standalone`, `start_url` and `scope` `/`, `theme_color` and
    `background_color` from the CLEAR skin's `--base`, and four icons including a `maskable`
    512 so Android's own mask does not crop the mark.
  - `icon.svg` — the mark, scalable, for `rel="icon"`.
  - `sw.js` — the app-shell worker.
- **`scripts/generate-pwa-icons.mjs`** (new) — renders the mark to PNG (192, 512, maskable 512,
  apple-touch 180) and exposes a Vite plugin that emits those files during `vite build` and
  serves the same bytes from memory in dev.
- **`index.html`** — manifest link, `theme-color`, SVG icon, `apple-touch-icon`,
  `apple-mobile-web-app-capable` / `mobile-web-app-capable`, app title, status-bar style.
- **`src/app/service-worker.ts`** + **`src/main.tsx`** — registration at `/sw.js` scope `/`, on
  `load`, `updateViaCache: 'none'`, off unless `import.meta.env.PROD`, failure swallowed.
- **`vercel.json`** — `Cache-Control: public, max-age=0, must-revalidate` on `/sw.js`.
- Tests: `src/test/service-worker.test.ts`, `src/test/pwa-manifest.test.ts`,
  `src/test/pwa-icons.test.ts`, `src/app/service-worker.test.ts`.

### Decisions, and why

**The icons are rendered by the build, not committed as binaries.** The export's
`assets/favicon.svg` sets a `C` in Oxanium and rounds its corners with `rx="6"`: a favicon loads
no webfont, and corner radius is 0 in this system. So the mark is drawn as geometry — orthogonal
and 45° edges only, per `assets/README.md` — with the `.clr-chamfer` bottom-right cut on the
badge and on both open tips of the `C`. The renderer is ~200 lines of scanline fill plus a
minimal PNG encoder over `node:zlib`; no image dependency was added.

**The renderer lives in `scripts/`, not `src/`.** It has to restate two hex values (`--base`,
`--structure`) because neither a PNG nor a manifest can read a CSS token. In `src/` that is a
DS-08 failure, and correctly so. `src/test/pwa-icons.test.ts` asserts both values still match
`src/styles/skin-clear.css`, so the restatement cannot drift silently.

**No stale-shell trap, at three layers:** the document is network-first with the cached shell as
the offline fallback only; the worker calls `skipWaiting()` on install and `clients.claim()` on
activate, and deletes every cache whose name is not the current version; and `/sw.js` is served
`max-age=0` so the update check itself is never answered from the HTTP cache.

**Nothing but the shell is cached.** Non-GET, cross-origin (Supabase, Anthropic), and same-origin
`/api/`, `/rest/v1/`, `/auth/v1/`, `/functions/v1/` requests are not handled at all — they fall
through to the browser's own network path, so there is no code path that could write them to a
cache. Fingerprinted `/assets/*` are cache-first because their URLs are immutable. This keeps
IA.md §5 true: data offline is still OFF-01 in M3.

### Failures and corrections

- The icon plugin first called `this.emitFile()` unconditionally, which Vite rejects in serve
  mode — every `vitest` run printed *"context method emitFile() is not supported in serve
  mode"*. Corrected with a `configResolved` flag: emit during `build`, serve via middleware
  otherwise.
- `src/test/pwa-icons.test.ts` asserted the SVG contains no `rx=`, and failed on the file's own
  header comment, which names the `rx="6"` it replaces. Corrected by stripping comments before
  asserting — the same distinction `src/styles/fonts.test.ts` draws between what a file requests
  and what it talks about.
- The worker is tested by evaluating `public/sw.js` against a fabricated worker scope rather than
  by grepping its source: a test that finds the word `skipWaiting` in a file proves nothing about
  a shell that loads offline. Requests are plain objects there because a real `Request` cannot be
  constructed with `mode: 'navigate'`.
