### Migration failures and corrections

1. `02-create-issues.sh` stopped before creating an issue with `REPO…: unbound variable`.
   Bash read the adjacent Unicode ellipsis as part of the variable name. The generator now emits
   `${REPO}…`; the same correction was applied to the dependency script template.
2. Issue creation then stopped safely after issue 66. Requirement OVR-01c contains quoted text in
   its title (`why this number`), and the generator had embedded titles directly inside shell double
   quotes. The generator now shell-quotes every generated argument with Python `shlex.quote`.
   The local ignored `issue-map.txt` checkpoint let the rerun skip issues 1–66 and create only
   issues 67–71.
3. The first live verification incorrectly reported 142 edges and no ready issue. GitHub returns
   `blockedBy` as an object with `nodes` and `totalCount`; measuring the object's length returns two
   for every issue. The corrected verification sums `blockedBy.totalCount` and tests that field for
   zero. No graph data was removed because the mismatch was in the query, not GitHub.

### Synchronization model

- The Mac is the working copy. A commit is a local checkpoint; a push sends that branch's commits
  to GitHub. GitHub does not continuously synchronize uncommitted files.
- `main` is approved work. One issue is implemented on one branch and merged through one pull
  request. After a merge, local `main` is updated with a fast-forward pull before new work starts.
- GitHub Issues are now the live build queue. `docs/requirements/REQUIREMENTS.md` remains the frozen
  v0.7 baseline; discovered scope changes belong on the live issue or a deliberate follow-up issue.
- `docs/github/issue-map.txt` is a local, ignored migration checkpoint. It maps requirement IDs to
  issue numbers and is not product source code.
