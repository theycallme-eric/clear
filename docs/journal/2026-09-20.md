# TASK-020 — CORE-05 accessibility contract (issue #19)

## Intended outcome

Build the shared cross-screen accessibility mechanisms every screen uses: route-change focus and
announcement, skip link, context-driven heading levels, landmark ownership, per-screen titles,
form-error focus, the reduced-motion end-state guarantee, and document-shell (lang/title/viewport)
coverage. Branch `agent-runner/task-020-a1-18e22a06`, isolated Agent Runner workspace.

## What changed

- `src/app/AppChrome.tsx` — new root layout route: renders the skip link first, an `<Outlet/>`,
  and a `role="status"` polite live region. On a `location.key` change (never the initial load)
  it focuses the new screen's `<h1>` (falling back to `<main>`) and announces the screen title
  once; the announcement span is keyed by navigation so repeat same-title landings still mutate
  the region exactly once. Child `Screen` effects run before this parent effect, which is what
  makes the registered title available at announcement time.
- `src/app/Screen.tsx` — the one screen wrapper: owns `<main id="main" tabindex="-1">`, the single
  focusable `<h1>` (custom `heading` content allowed, announcement still by `title`), the
  per-screen `document.title` (`Name · CLEAR`, bare `CLEAR` for the app-named screen), and starts
  child heading context at level 2.
- `src/app/screen-registry.ts` — context through which `Screen` reports its title to `AppChrome`.
- `src/ui/Heading.tsx` — `Heading` takes its level from context; `HeadingSection` is the only way
  one level deeper (clamped at h6), so skipped levels are unrepresentable. `HeadingLevelProvider`
  pins a subtree level (used by `Screen`).
- `src/ui/Nav.tsx` — the app's `<nav>` with a required accessible-name `label` prop.
- `src/ui/SkipLink.tsx` + `src/styles/a11y.css` — visible-on-focus skip link (tokens only),
  `.a11y-hidden` utility, and the reduced-motion end-state block (durations collapse to 0.01ms
  rather than `animation: none`, so fill states resolve; vendored motion.css keeps handling the
  design system's own vocabulary). Imported last in `src/main.tsx`.
- `src/ui/formFocus.ts` — shared `focusFirstInvalid` submit helper (export pattern 1):
  `[aria-invalid="true"]`/`:invalid` in DOM order, with a fallback for selector engines without
  `:invalid`.
- `src/ui/motion.ts` — `prefersReducedMotion()` for app-composed JS animation.
- `src/app/router.tsx` — routes nested under `AppChrome`; `AppShell`/`NotFound` now render through
  `Screen`.
- Tests: `src/app/AppChrome.test.tsx`, `src/app/Screen.test.tsx`, `src/ui/Heading.test.tsx`,
  `src/ui/Nav.test.tsx` (includes the AppHeader `banner` landmark assertion),
  `src/ui/formFocus.test.tsx`, `src/ui/motion.test.ts`, `src/test/document-shell.test.ts`
  (lang="en", default `<title>`, zoom-safe viewport asserted against `index.html`).
- Docs: DEVELOPMENT.md gains the keyboard-only and screen-reader review passes; PROJECT_MAP.md
  flow updated to `… router.tsx → AppChrome → screens`.

## Decisions and corrections

- `axe-core` wiring belongs to the E2E suite (ENV-07), which does not exist yet; REQ-020 itself
  labels it "(ENV-07)". Not widened into this task.
