## Intended outcome

shared helpers, EmptyState usage rules, a slow threshold, and a top-level error boundary. Branch
`agent-runner/task-019-a1-4912f917`, isolated Agent Runner workspace, left unpushed.

## What changed

- `src/state/view-state.ts` — closed `ViewState<T>` union, constructors, `viewStateFromResult`
  (maps `Result<T>` onto the contract; success with nothing to show is `empty`, not `ready`),
  `SLOW_THRESHOLD_MS` (4 s app-wide default) and `useSlowThreshold`.
- `src/ui/view-state.tsx` — shared renderers: `LoadingView` (ScanLoader; switches to honest `slow`
  status + "Taking longer than usual" past the threshold), `ErrorView` (EmptyState in the
  toast-negative urgency frame, `role="alert"`, AlertTriangle glyph, AppError message + requestId +
  retry), and the exhaustive `ViewStateSwitch` with a deliberately non-defaulted `empty` slot.
- `src/app/ErrorBoundary.tsx` — top-level boundary wrapping the router in `src/main.tsx` and in the
  shared test providers (`src/test/render.tsx`). Recoverable screen with a Reload action; the thrown
  error's own text never reaches the screen; crash reported through the structured logger (CORE-02).
- `docs/conventions/state-contract.md` — the documented contract, alongside `error-handling.md`.
- `PROJECT_MAP.md` — flow line now includes the boundary and the contract modules.
- Tests: `src/state/view-state.test.ts` (model), `src/ui/view-state.test.tsx` (reference
  History-style screen simulating all four states, the slow threshold, and retry re-running the
  operation), `src/app/ErrorBoundary.test.tsx` (crash → recoverable screen, no raw error text or

## Decisions and assumptions

- No spec defines the slow threshold number; chose 4000 ms as the app-wide default and documented

# TASK-026B / DS-04b — Select (issue #26, attempt 2)

## Intended outcome

The native CLEAR `<select>` — real platform control wired through `FormField` with Input's aria
contract, styled from tokens as Input's visual sibling, dropdown left to the platform. Branch
`agent-runner/task-026b-a2-0aab270d`, isolated Agent Runner workspace.

## State inherited from attempt 1

The workspace opened clean at main (5cf486f) with no attempt-1 artifacts, so the prior

## What changed

- `src/ui/select.tsx` — `Select`: a real `<select>` (keyboard behaviour, type-ahead and the
  mobile picker stay native) rendered through `FormField`'s render-children, taking `describedBy`
  and `invalid` from it and applying `aria-describedby` / `aria-invalid` exactly as Input does
  (`invalid` prop overrides the errorText inference; `aria-invalid` omitted when valid). Inline
  token styling mirrors Input's: `--border-width` structure border with the same
  border/surface state ladder (`--border-input`/`--surface-input`, focus →
  `--border-card`/`--surface-input-active`, invalid → `--border-input-invalid`/
  `--surface-input-invalid`, disabled → `--border-disabled`/`--surface-disabled`),
  `border-radius: 0`, body font tokens, `--spacing-*` padding, the shared
  `--dur-state`/`--ease-mech` transition. `appearance: none` strips only the closed control's
  platform chrome; a decorative, `pointer-events: none` `ChevronDown` (already `aria-hidden` in
  the export) sits in the `--spacing-800` right padding. Options come from a flat
  `options: {value, label, disabled}` array (ChoiceGroup's shape) or native `<option>` children
  for grouping; `multiple`/`size` are typed out because they turn the control into an inline
  listbox. `onChange(value, event)` matches Input's callback shape.
- `src/ui/select.test.tsx` — 14 tests written first, one per acceptance angle: real
  HTMLSelectElement with native options and form participation; children-as-options; the full
  FormField aria contract (label via `htmlFor`, helper/error described-by order, implied and
  overridden `aria-invalid`, required asterisk); token-only visuals including the focus
  brighten/settle cycle and invalid/disabled states; decorative non-interactive chevron; and no
  custom listbox — no `listbox` role, no `aria-haspopup`/`aria-expanded`, only `<option>` children.

## Failures found and their actual causes

- First test run: 99/100 — jsdom's CSSOM normalizes `border-radius: 0` to `'0px'`, so the
  strict string equality assertion failed. Rewrote the assertion as
  `toHaveStyle({ borderRadius: '0px' })`. No component change needed.

## Decisions and assumptions

- Placed in `src/ui/` per PROJECT_MAP; ATOMIC.md §11 marks Select as a DS-04-owned gap, and no
  `.clr-select` CSS exists in the export, so the component carries its styling inline exactly as
