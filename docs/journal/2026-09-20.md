# TASK-030 / DS-08 — adherence gate in CI (issue #31)

## Intent

Turn the standing constraint into a failing build: `npm run lint:ds` over `src/`, consuming the
vendored `_adherence.oxlintrc.json` with every rule raised from `warn` to `error`,
`src/design-system/` excluded, fixtures proving it bites, wired into CI before the first screen
ticket. Branch `agent-runner/task-030-a1-7ad373cb`, based on main at 9534e7a.

## Deviation: the engine is ESLint, not the oxlint binary

The requirement names oxlint. The workspace has no network access — `npm install`, `npm view`,
`npx <uncached>` and direct registry requests are all refused by the sandbox — so the oxlint
binary could not be added, and a script that fetched it on demand would fail the mandatory
local `npm run lint:ds` verification. The gate therefore runs on ESLint 10, already a
devDependency, which implements `no-restricted-syntax` and `no-restricted-imports` with the
same esquery selector semantics the export's rules are written against. Nothing about the rule
set is retyped: `scripts/adherence/ds-config.mjs` reads the vendored JSON and raises it.
Swapping in oxlint later is a change of runner, not of rules. Flagged for Eric — if the
oxlint binary is wanted specifically, it needs a dependency added in an environment with a
registry.

## What changed

- `scripts/adherence/ds-config.mjs` — builds the flat config from the vendored export: raises
  every severity to `error`, ignores `src/design-system/**`, carries over the export's own
  `**/index.js` override, and sets `noInlineConfig` so a disable comment cannot reopen the
  negotiation.
- `eslint.ds.config.js` + `"lint:ds"` in package.json — `eslint --no-config-lookup --config
  eslint.ds.config.js src`. Separate from `eslint.config.js`: adherence, not code health.
- `scripts/adherence/fixtures/` — one deliberately broken file per named violation (raw hex,
  raw px, foreign font, unknown prop, out-of-range variant, component-internal import), plus a
  disable-comment probe and a compliant control. Added to `eslint.config.js` ignores; outside
  `src/`, so neither `lint:ds`, tsc nor vitest collects them.
- `src/test/adherence-gate.test.ts` — 11 tests: each violation reported as an error (never a
  warning), the disable comment ignored, the compliant control silent, the vendored bundle
  ignored despite carrying raw px, and the vendored `warn` severities proven raised.
- CI `Lint` job runs `npm run lint:ds`; README documents the command and every relaxation;
  PROJECT_MAP gains the `scripts/adherence/` row.

## Findings, and the two relaxations they forced

- The first run failed on existing, correct code: `<Dialog onCancel>` in `src/ui/app-dialog.tsx`
  (TASK-027). `DialogProps extends React.DialogHTMLAttributes`, so `onCancel` is declared,
  inherited and type-checked — but the export's generated prop list carries only each
  component's *own* props, so every inherited DOM attribute reads as unknown. 16 of the 18
  components inherit this way. The gate now drops the unknown-prop rule for components whose
  vendored `.d.ts` extends a React DOM attributes interface, detected from the typings rather
  than hardcoded, and keeps it for the closed-prop ones (EmptyState, TimerDisplay). Nothing is
  lost for this repo: those interfaces are closed to typos, so `tsc --noEmit` — already a CI
  gate — rejects `<Button colour="red">` exactly. Every enum range stays enforced everywhere.
  This is a defect in the vendored rule set, the same family as the ATOMIC §15 list; worth
  reporting upstream on the next design-system pass.
- Tests legitimately write `'0px'` when reading a rendered value back (`toHaveStyle({
  borderRadius: '0px' })`, from TASK-026B). Only the three raw-literal rules relax under
  `**/*.test.{ts,tsx}` and `src/test/**`; props, enums and imports stay enforced there.
- The export's import patterns are written for bare specifiers (`components/Button/**`), which
  never match CLEAR's relative `../design-system/...` imports. Each internal group is expanded
  with a `**/design-system/` form. `index.js` and `skin.js` are deliberately not expanded —
  they are the public entry and the skin initialiser.
