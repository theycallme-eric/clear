## TASK-004 / #350 — shared field, select and quiet-action scaffolding

Intended outcome: bring the app-owned form scaffolding onto the 0.14.3 field
contract (REQ-007/008/009) on branch `agent-runner/task-004-a1-77f64946`,
inside the owned set `src/ui/select*`, `formFocus*`, `checkbox-group*`,
`inline-save*`, `text-action*`. No route, global style, gallery or shared
adapter outside that set was touched. Nothing was pushed.

What changed locally:

- `src/ui/select.tsx` — the native `<select>` now sits in the same element
  frame the public Input emits (`clr-bleed clr-bleed--block` >
  `clr-chamfer clr-chamfer--sm clr-field` > `.clr-input`). Border, surface and
  bleed moved from the control to the frame; focus uses
  `--border-field-focus` and wins the border over invalid while the surface
  keeps the urgency tint, matching Input.jsx. An invalid, enabled select now
  carries Input's in-field warning glyph. The literal 40 minimum height became
  `var(--control-height)`, and the FormField root releases `min-width` so a
  narrow parent can shrink it. Props and the `(value, event)` change shape are
  unchanged, so no consumer call site changed.
- `src/ui/text-action.tsx` (new) — the app adapter. The public TextAction
  renders a button or a plain anchor; a plain anchor to an in-app path reloads
  the document, so `to` renders a router `Link` wearing the public
  `clr-text-action` class. Without `to` it is the public component unchanged.
  No route consumes it yet; adoption belongs to the route tasks.
- `checkbox-group.tsx`, `inline-save.tsx`, `formFocus.ts` — reviewed against
  0.14.3 and left unchanged. Their APIs are frozen as they stand for the
  Settings/Places tasks.
- Tests: `select.test.tsx` rewritten around the frame; `formFocus.test.tsx`
  and `checkbox-group.test.tsx` extended; `text-action.test.tsx` added.
