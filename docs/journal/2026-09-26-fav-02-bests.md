## Intended outcome

The one acceptance criterion the task carries: *personal bests are derived only from comparable
completed performances and identify the source workout.* TASK-059 (#177, already on `main`) built
the derivation — `personalBests`, MIN time / MAX rounds, strict improvement only, cap-stopped clocks
refused. What it did not do is fence the *input* against readings that are not performances, or make
a record say where it came from beyond a bare day.

## What “comparable completed performance” resolves to, and why

The phrase had two plausible readings and the spec settles it. favorites-v2 §Incomplete Attempt:
a workout the user bailed out of does **not** increment `times_completed`, and *“timed sections
completed: count toward the Previous Best pool.”* So the unit of a completed performance is the
**block**, not the session — a run that was abandoned still holds records for the blocks it
finished. Every test a reading has to pass is therefore block-level, and nothing added here
disqualifies a reading because of the state of the session around it. This is written into the
module header so the next reader does not re-litigate it.

Three ways a reading is not a record, two of them new:

- **Not a performance.** `SES-01b`'s `session_reconstruction` attaches `block_result` for *all
  three* kinds (verified in `supabase/migrations/20260921000009_session_reconstruction.sql`), so a
  `generated` or `intended_at_start` payload carries scores that were never performed. `runMeasures`
  now returns nothing at all for a reconstruction other than `performed`. This is the “inferred
  result” the objective names: previously only the module's doc comment said the input had to be
  `session_as_performed`, and a doc comment is not a guard.
- **Not the same work.** A block whose slot was swapped (EXE-04 — the dependency FAV-02 has always
  declared) or whose movement was skipped scored different work against the same clock. Read off the
  prescriptions via the existing `prescriptionLineage` (`replaced` / `substituted`) plus
  `execution_status = 'skipped'`, because `block_results` says how the clock ended and nothing about
  what was under it. The block's *score* is dropped; its movements' top sets still read, since a top
  set is keyed by the movement and is a fact about that movement either way.
- **Not a finish.** Cap-stopped For Time, unchanged from TASK-059.

## What landed

- `src/state/favorite-progression.ts`
  - `runMeasures` refuses a non-`performed` reconstruction outright, and drops the timed score of a
    block that failed `sameWorkAsPrescribed` (new, private).
  - `PersonalBest` gains `sessionId` and `workoutTitle` beside `setOn`: the day it reads as, the
    session in History holding the evidence, and what that workout is called. The source moves with
    the number and only with the number — equalling a best leaves both where they were set.
  - `CompletionEntry` gains `holdsBest`, the other end of the same fact: the run that holds a
    current record says so on the line the user is scanning.
- `src/ui/favorite-progression.tsx` — the badge reads `Personal best · set Tue 8 Sep 2026 · Full
  body`, and the completion that holds a record carries the same word (glyph *and* word, never
  colour alone).
- `src/dev/gallery-registry.tsx` — the FAV-02 specimens carry the new fields, kept internally
  consistent (run 3 holds the time, run 2 the rounds, run 1 nothing).
- Tests: 13 new. `src/state/favorite-progression.test.ts` covers the refusals (intention, swap,
  skip) at both `runMeasures` and `personalBests` level, that a cap-stopped or altered run leaves
  the real record standing, and the source naming; `src/ui/favorite-progression.test.tsx` covers the
  badge naming the workout, the marked completion, and a favorite whose every attempt hit the cap —
  two completions listed, no record claimed.
