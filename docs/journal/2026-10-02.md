## Decisions and assumptions

- Any failing row refuses, not only rows that block the proposed goal. REQ-010 defines a viable
  configuration as one where every goal and focus Generate offers resolves, active recovery included,
  and the commit uses that definition unchanged. A section only recovery asks for gets a sentence
  that does not offer "turn it off".
- The refusal travels as the exception's DETAIL rather than a second `generation_viability` call from
  the client, so the rows named are the ones the transaction judged.
- `CLR11` is a custom SQLSTATE. PostgREST's documented default for an unrecognised code is HTTP 400;
  the client keys on `pgCode`, not on the status, so a different status would still be recognised.
- The refusal stays on the confirm step rather than jumping to the step that owns the named choice;
  Back reaches it with every value intact.
