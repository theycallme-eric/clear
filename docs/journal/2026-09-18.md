## TASK-017 / CORE-02 — Structured logger with redaction (issue #16)

**Intended outcome.** Implement the redacting structured logger for client and edge runtimes and
activate a lint ban on raw `console` usage. Branch: `agent-runner/task-017-a1-e1aeb111`, an isolated
Agent Runner worktree. No push, PR, or merge — the controller verifies independently.

### What changed

- `src/state/logger.ts` — new. Leveled JSON-line logger (`debug`/`info`/`warn`/`error`, default
  `info`) with scoped children and bound fields. Redaction is structural: a case-insensitive
  denylist (`authorization`, `apikey`, `token`, `secret`, `password`, `cookie`, `session`,
  `credential`, `bearer`, `email`, `jwt`, …) masks matching keys at any nesting depth; string
  values that look like bearer tokens, JWTs, or email addresses are masked even under safe keys;
  `Headers`, `Map`, and duck-typed header containers are replaced wholesale, so a raw header map
  cannot be logged. Fixed entry keys (`level`, `msg`, `time`, `scope`) are applied after caller
  fields so they cannot be spoofed. `logEdgeRequest`/`formatEdgeRequestLine` emit exactly one line
  per request with explicitly picked fields — `requestId`, `route`, `status`, `durationMs` — so
  nothing else on the input object can reach the line. A `redact()` helper is exported for
  sanitizing data at boundaries.
- `src/state/logger.test.ts` — new, 15 tests: denylist proof that `authorization`/`apikey` values
  never appear in output (flat, nested, and via a real `Headers` instance), email/bearer/JWT value
  redaction, circular-structure safety, level filtering, JSON-line shape, fixed-key spoof
  resistance, child scope/bound-field behavior, and the edge line contract (exact key set; header
  values dropped even when spread into the summary).
- `eslint.config.js` — `no-console: 'error'` added to the app-wide rules, with a single sanctioned
  exception for `src/state/logger.ts`, whose default sink binds the global logging object once
  (written so the literal text `console` followed by a dot never appears in `src/`, keeping both
  the CI git-grep gate and the controller's raw grep clean). The pre-existing CI grep gate in
  `.github/workflows/ci.yml` (from ENV-02) is unchanged and still applies.
