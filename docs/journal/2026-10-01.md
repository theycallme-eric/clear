# 2026-10-01 — CLEAR 0.9.7 VIBE-C: Review, Workout, Summary

Issue #273 applies the authoritative CLEAR Design System 0.9.7 package (SHA-256
`12620dc5d9b6d7de965f25b80f86a90b8ee3e6a5eeea813eb1b85b0563d74790`) to the
post-generation workout journey without changing its product behavior.

## What changed

- Review now uses an app header, compact semantic metric frames, accent workout cards, and a
  measured footer containing Regenerate and Start. The no-review recovery action follows the same
  footer rule.
- Workout keeps logging and coaching in the one contained scroller while the rest state and
  Previous/Next/Finish navigation remain reachable in the measured footer. The final-ten-second
  rest milestone has one polite announcement; the design system's stepped 400ms urgency and 80%
  pulse remain reduced-motion safe.
- Summary explicitly renders loading, error, empty, and ready states. Duration and streak use
  compact result frames, Favorite remains a distinct functional card, and Save and close submits
  the scrolling debrief form from the measured footer.
- `MetricGrid` and `MetricFrame` are shared composition vocabulary with gallery examples for
  resolved, loading, even, and odd result sets, so later geometry and spacing corrections cascade.
- The browser suite now has a deterministic real-data Review → Workout → Summary → Home walk on
  phone and desktop. It checks accessibility, keyboard reachability, footer containment, actual
  persistence, and captures all three screens without spending a model call.

## Friction and what it meant

The first model-backed core-loop run spent its five-minute allowance looking for a Goal control on
Generate. That locator predated the approved intent restoration: onboarding persists the standing
Goal, Generate displays it as context, and a first workout asks only for the unresolved Focus
(currently labelled Anchor in the UI). The journey now asserts the saved Goal text and waits no
more than 30 seconds for the Focus control, so this class of drift fails quickly.

After that correction, both phone and desktop reached the deployed generation function and received
the same typed `GENERATION_MODEL_ERROR` / HTTP 502. The failure occurred before Review and is an
external model-service boundary, not a visual defect. No fixture replaced that live assertion and
no repeated paid-call loop was introduced. The added persisted-session walk keeps visual work and
post-generation lifecycle verification available while the provider boundary is investigated.

The first full unit run found the new metric components had only one gallery state. That was a real
gallery-contract miss, not a product failure; resolved/loading and even/odd specimens now keep the
shared pattern reviewable.
