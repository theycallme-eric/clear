# 2026-10-01 — provider failure made actionable

VIBE-D merged through the normal protected path, but both post-merge checks stayed honestly red at
the same boundary: 102 trusted-backend checks passed before live composition returned 502, and the
exact production deployment's new-user journey reached the same response. The Supabase function
log shows context resolution and prompt assembly succeeded before both provider attempts failed as
`generation.upstream` in well under two seconds.

The runtime had enough information to distinguish the provider response internally, but the
structured warning logged only the broad failure code. That made an invalid key, insufficient
credit, a malformed request, a quota limit, and provider overload operationally indistinguishable.
`claude.ts` now includes its already-sanitized attempt detail in the warning. That detail is only an
HTTP status, exception name, schema path, or validator explanation; provider bodies, prompts,
headers, and keys are never copied into it. Tests prove a simulated 529 is visible on both attempts
while its response body and API key remain absent.

The live secret inventory supplied the other concrete clue: `ANTHROPIC_API_KEY` exists but its
deployed value was last updated on 21 January 2026. Paying or creating a key in a different
Anthropic workspace cannot repair that old stored value. Once this safe logging repair is deployed,
one bounded live call will name the exact provider status before any secret is replaced; the
replacement, if required, must be made directly in Supabase and never pasted into chat or committed.

This is a reusable automation lesson: a provider gate needs three separate proofs before dependent
work is called runnable—secret name present, credential updated for the intended workspace, and a
minimal capability probe that records a non-sensitive upstream status. Presence alone is not
capability.

# 2026-10-01 — paid model test containment and provider-diagnosis correction

Issue #284 records a recurring cost leak discovered while reopening TASK-014 and VIBE-D. The
3,000-plus unit tests are deterministic and do not call Anthropic. The paid traffic came from two
workflow paths: every merge to `main` ran the live generation/persistence spec, then every successful
Production deployment ran the model-backed core loop. The small-PR DAG therefore multiplied a
roughly $0.06 acceptance call across normal integration activity.

The prior provider note also made an unsupported inference: it treated the January Supabase secret
timestamp as proof that the key belonged to a different Anthropic workspace. A read-only check of
the funded console showed the `clear-supabase` key in that same workspace, created on the same date,
with current-month usage. The correction is: the deployed credential belongs to the funded
workspace; the remaining HTTP 400 still needs a secret-safe provider classification or a later
bounded canary. Replacing the API or key is not justified by the evidence currently available.

The containment change makes all routine CI and automatic deployment journeys model-free. One
explicit release canary owns the recurring real-model proof, has a fixed concurrency group, disables
Playwright retries, declares one expected generation (one provider attempt normally, two at most for
a retryable failure), and walks the complete deployed core loop so the same generation is reused for
Review, persistence, Workout, Summary, and Home evidence. Paid specs also require an explicit
`LIVE_MODEL_TESTS=1` opt-in, so a credentialed local run cannot multiply them across three viewports.
The composer now
retries only failures that can change on an identical second request (network, rate limit, or provider
service); deterministic 400/401/403/404 responses stop after one attempt and log only a safe category.

Verification completed without a live model call:

- focused provider and workflow policy tests: 56 passed;
- credentialed Playwright invocation of both paid specs without `LIVE_MODEL_TESTS=1`: 4 skipped;
- full unit suite: 169 files, 3,177 tests passed;
- design lint, app lint, typecheck, and production build: passed;
- build retained the existing bundle-size advisory.
