Findings and their dispositions:

- **TextAction's chevron is part of the link's accessible name in a browser**
  ("View history ›"). History renders no `TextAction`, so this touches neither
  of this task's acceptance criteria and nothing History's dependents consume;
  the only contact was this spec's Home locator, fixed and verified above. It
  is shipped 0.14.3 vendor CSS on a Home control (TASK-004 / TASK-013 own the
  adapter and the consumer). Whether a screen reader announcing the chevron
  warrants an adapter exception is an owner decision under the component
  authority note; this task did not change it and is not blocked by it.
- **Pinned-action geometry read mid-animation.** Fixed in this spec and verified
  (18/18). `e2e/core-loop.spec.ts` carries the same helper and may show the same
  timing-dependent failure on Review; it is outside this task's ownership and
  was neither run nor edited. It touches neither acceptance criterion here.
- **Header back control.** The application reference uses a
  `ui/header-back-button` this repository does not have; Generate, Session
  Detail and Location Settings all use the same framed quiet `Button` with
  `ArrowLeft` that History keeps. Left as is: header chrome is shared, not
  History's collection, and neither criterion names it.
- **Card heading and list label are both "Workout history".** Deliberate, and
  the same pairing Home uses for Recent workouts and Favorites.
- Retry, "Show all entries" and "Load older workouts" stay in the pinned footer
  as the screen's single primary action. `ViewStateSwitch` is still given no
  `onRetry`, so the error state shows one Retry, not two.
