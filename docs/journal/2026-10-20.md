## TASK-037 (#472) — null-safe history readers and the persisted-prescription trace

Intended outcome: prove that the strength-anchor, progression, conditioning, training-history and
weight-fill readers handle absent `rpe`/`perceived_effort` in new and mixed historical sessions,
and trace an existing rule's adjustment into the next persisted prescription. Branch
`agent-runner/task-037-a1-e64a2ded`. Nothing was pushed and no external service was touched.

Finding: every reader was already null-safe, so no production code changed. `e1rmCandidate` drops a
set with no RPE, `sessionRead` takes the median of the RPE that was recorded, and every RPE rule
needs a recorded value. `conditioningTrend` will not count an unrecorded effort as easy. No reader
defaults effort or reads feeling, and none rewrites its input rows. The only rules that still fire
without RPE are `overshoot-missed-reps` and conditioning `backing_off`, and both read outcomes
(reps or the cap), not effort.

Trace: a missed-reps back-off on a session with no RPE goes from `reviewLoadSuggestions`
(82.5 → 77.5 kg) through `applyLoadOverrides` into the accepted prescription as
`absolute 77.5`. With no override the persisted prescription is unchanged, so no suggested number
is stored as a load the athlete chose. Neither persisted path writes a performed field. No handoff
mismatch was found, so nothing was corrected.

Tests added: anchors (state 3, data 3), progression (8), conditioning (4), training-history (2),
weight-fill (3).

Process correction: one new data-anchor test first expected 133.33. The correct value is 123.33,
because 5 reps at RPE 8 is 7 effective reps, not 10. This was a test-arithmetic error, and the code
was right.
