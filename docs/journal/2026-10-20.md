  `completeBlock(id, outcome, { perceivedEffort })`, which TASK-022 will use. A ref-held in-flight
  set means a repeated call cannot write twice. Already-recorded and unknown blocks are still
  refused, a failed write is still handed to `onFailure` and leaves the block completable, and the
  existing dialog flow is unchanged.
