# 2026-08-25

## What happened

**The design system landed and rewrote the DS layer.** `CLEAR Design System 0.5.0` turned out to
be a complete component library, not a token export — 18 typed React components, 75 icons, four
skins, a three-level atmosphere axis, contrast measured by rasterizing rather than computing, and
a lint config that mechanises design-system compliance. It shipped more than the DS trunk proposed
to build. DS-03 deleted outright; DS-01/02/05/06 rescoped from *build* to *integrate*; DS-07
shrunk to serving 38 specimen cards that already exist; DS-08 added to raise the export's own
adherence rules from `warn` to `error` in CI.

`docs/specs/design/ATOMIC.md` written — the substrate contract IA.md had been pointing at since
yesterday. 433 lines: provenance and version pin, the three-layer architecture, role slots and the
alpha ladder, 332 tokens by kind, every component's real prop API, the two global attributes, the
motion vocabulary, the inherited accessibility guarantees, the three gaps the export does not
cover, and 14 non-negotiables. Plus three defects found in 0.5.0, recorded so a future upgrade can
check them.

**Two decisions taken.** No bottom sheets — every overlay is a `Dialog`, and what a sheet was
really offering (arrival) comes from the motion vocabulary instead. Fonts self-hosted — not for
offline, which was the weak argument I over-weighted, but because the export's nested `@import`
chain is four sequential render-blocking hops and CLEAR is uppercase Rajdhani and Oxanium on
nearly every surface.

**The eight backlog stubs resolved.** Five cut, two promoted, one folded. Each cut recorded in
`docs/requirements/DEFERRED.md` with the specific signal that would reopen it — the point being that a
cut idea returns with new evidence, not new enthusiasm. D7 registered along the way (set logs
written live with no failure handling) and EXE-07 written to close it.

**v0.6 — the three gaps an outside review had found.** Six oversized requirements split, each
having to name the dependent it unblocks. Test architecture added (ENV-06, ENV-07) with a mobile
viewport as the *default* Playwright project and RLS as a standing test rather than a one-time
check. Accessibility contract added (CORE-05) carrying only what the design system cannot know.

**The scripts became generated.** `scripts/gen-issues.py` parses REQUIREMENTS.md and emits both
issue scripts and all 71 bodies, and validates the graph. It immediately caught four requirements
still depending on DS-03, deleted two commits earlier — exactly the drift hand-maintenance
produces. ENV-02 now runs `--check` in CI.

**The DAG playbook, corrected.** It had been parked as retrospective method documentation. Eric:
*"I want to use the DAG to help direct agents to build the platform, so it needs to be before the
build, period."* That reframed it entirely — it is an operating instruction, not a write-up. He
was right and the filing was wrong. `docs/process/AGENT_PLAYBOOK.md`, `scripts/gen-dag.py`, `docs/DAG.md`,
and `CLAUDE.md` all written.

**Toolchain.** gh 2.83.2 was on the machine — below the 2.94.0 floor that dependency flags need.
Homebrew installed (it wasn't there), gh upgraded to 2.98.0.

**A readiness audit, at Eric's insistence, before cutting issues.** He was right to stop. Four
real gaps found — see STATUS thread 0.

## What was learned

**"Feels empty" is worth investigating, not reassuring away.** Eric said the generation and schema
work felt thin. The schema is 575 lines of real DDL, so the instinct was to say so. Auditing
instead found the actual thing: the v4.1 prompt does not exist, and the v3 prompt's composition
rules — the accumulated thinking about what makes a good workout — sit in a document whose
architecture is superseded, with nobody having written that down. A vague worry pointed at a
specific hole.

**The design system was told to hide its own best asset.** `ui_kits/app/` recreates six screens
faithfully, and ATOMIC.md described it as "a worked example, not a library surface" — accurate
about its *code* status and actively misleading about its *design* status. Two different questions,
one sentence, and an agent reads it as "ignore this folder."

**Splitting a requirement lengthened the critical path and that was fine.** DATA-01 → a/b/c/d
added three steps to the longest chain. The migrations were always sequential — foreign keys
decide that, not tickets — and the split bought DATA-02 an earlier start. Counting steps finds the
chain that matters; treating the number as a score would have argued against a good change.

**Two errors worth not repeating.** I named a release asset (`macOS_arm64.pkg`) that does not
exist — the pkg is universal — and sent Eric looking for a file on a page whose asset list is
collapsed by default. Guessing a filename to sound specific cost him twenty minutes and a
Gatekeeper detour. And I over-weighted offline as the reason to self-host fonts; he pushed back
on it three times before I checked and found the real reason was the render path.
