## TASK-005 / issue #244: prompt-size and Focus-candidate regressions (REQ-012, REQ-013)

Branch: `agent-runner/task-005-a1-833e9e61`. Tests only, in `src/test/generation-prompt.test.ts`;
no prompt text, production code or fixture file changed. Nothing was pushed and no GitHub state was
changed.

What was added, after every existing assertion (all of which are untouched):

- A byte-budget regression pinning the fixture prompt's `totalBytes` to a pre-recovery baseline of
  12,340 with a 256-byte tolerance, justified in a comment beside the constants.
- Exactly one `goal:` line and one `focus:` line in the user message, and the requested focus value
  restated nowhere else except the `recent_focuses` history line.
- The system prompt carries no `goal:`/`focus:` line, no `session_focus` value, and is byte-identical

- Focus fixtures: the retrieval double over the committed seed, same user, location and sections,
  with only the focus changed. `lower_body` admits `back-squat` and not `bench-press`; `upper_body`
  the reverse; each side's exclusive primaries outnumber the shared ones.

Misleading signals, and what they actually were:

- The task and REQ-012 describe the fixture as "roughly 10.4 KB". On current `main` it measures
  12,340 bytes; the difference predates this recovery (the 5.1.0 TRAINING HISTORY and session
  directive work). The baseline in the test is the measured number, not the quoted one. The existing
  legacy-ratio assertions (< 0.6, < 0.65) still pass at this size.
- A first draft asserted the two primary sets share nothing. They share four: `barbell-row`,
  `pendlay-row`, `split-jerk`, `thruster`. The catalog gives each a pattern from both focuses, so
  this is the mapping working, not a leak. The test now asserts that a primary appears in the other
  focus's set exactly when it carries one of that focus's patterns. The acceptance wording
  "disjoint admitted candidates" is therefore met as "each excludes candidates the other admits",
  which is what the objective and REQ-013 state; full disjointness is not true of the seed.
- The system prompt cannot be asserted free of goal names: GOAL SHAPES names every goal as
  vocabulary. The test asserts request-independence instead.

Limit worth knowing: the Focus fixture runs the migration's predicate as transcribed in
`src/test/candidates-double.ts`, not Postgres. That is the same boundary the existing retrieval
tests state.
