# Generation reliability recovery — resolved owner decisions

The three product decisions the recovery brief (`CLEAR-GENERATION-RELIABILITY-RECOVERY.md`,
"Resolved owner decisions") records as settled. They are copied here verbatim so that the
section-mapping ledger and the configuration dispositions can cite them from inside the repository.
This file adds nothing to them; if the brief changes, this file is wrong until it is updated.

1. **Minimal equipment means low/no-equipment training.** Bodyweight, calisthenics, plyometrics,
   bands, and similarly appropriate work should form a useful workout. Minimal is not a degraded
   barbell program and should not disable ordinary Goals merely because no heavy implement exists.
2. **The owner does not re-author the section taxonomy.** The section intent already existed. The
   recovery reconstructs `skill_power`, `carries`, and `stability_balance` membership from the old
   catalog, previous migrations, workout-anatomy evidence, names/roles/patterns, and recorded product
   decisions. Agents may surface a genuinely ambiguous exercise with evidence and a recommendation;
   they may not hand the entire classification job back to the owner or invent a replacement model.
3. **Impossible preferences are rejected when saved.** Onboarding, Settings, and equipment changes
   may not persist a configuration that candidate retrieval already knows cannot generate. The
   refusal names the incompatible choice and leaves the previous valid state intact.

The brief's GR-02 workstream states the Minimal gap the first decision resolves, also verbatim:

"The current catalog contains no Minimal-compatible exercise marked `can_be_primary`; the repaired
taxonomy/preset must support meaningful main work without treating a barbell lift as the only
possible session anchor."
